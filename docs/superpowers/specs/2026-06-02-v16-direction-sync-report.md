# EcomPilot V1.6 方向同步报告

- 日期：2026-06-02
- 当前基线线程：`V1.6-00 方向冻结与文档基线`
- 结论状态：通过
- 本次性质：方向同步、范围冻结、文档更新
- 本次不做：大功能实现、schema 变更、migration、依赖变更、竞品截图收件箱落地、自动内容工作流落地、API 生图扩展

## 1. 总体理解结论

EcomPilot 已完成 MVP、V1-Core、V1-Plus、V1.5 与 V1.5 Stabilization。当前进入 V1.6 真实使用验证与主流程调整阶段。

后续主方向不再是“用户分别进入多个工具页，手动填多张表”，而是逐步调整为：

`图片/截图 -> 灵感箱扫描 -> AI 商品草稿 -> 草稿初筛分 -> 用户保留/放弃/转商品 -> 正式商品 -> 正式评估 -> 条件式内容生产`

核心分层如下：

1. 灵感阶段回答：这条图片线索值不值得继续看。
2. 商品阶段回答：这个正式商品值不值得小批量测试。
3. 自动化阶段回答：这个商品值不值得投入内容生产成本。

## 2. 总方向与范围冻结

后续阶段继续坚持以下原则：

1. 用户负责收集图片、截图，并确认关键结果。
2. 系统负责扫描、识别、生成草稿、组织数据。
3. AI 负责辅助提取信息、生成草稿、给建议和做初筛。
4. 正式商品、正式竞品、正式评分、文件删除等关键动作必须用户确认。
5. 继续禁止平台爬虫、自动采集、自动打开平台页面、浏览器自动化、Cookie、登录态、绕过反爬、自动上架、自动私信、自动评论。

V1.6 同时冻结以下边界：

1. V1.6 是真实使用验证版。
2. V1.6 不做大功能。
3. V1.6 不落地竞品截图收件箱。
4. V1.6 不落地自动内容工作流。
5. V1.6 不做 API 生图扩展，也不把 API 生图作为当前主流程目标。
6. 不因链接导入体验不佳而转向平台解析器或爬虫方案。
7. 不把截图识别或 AI 草稿直接写入正式商品、正式竞品、正式评分。
8. 不把“删除商品”升级为自动删除所有文件或自动补位真实 ID。

说明：

- V1.5 已存在“可选、手动、单次触发”的 API 生图能力，但它不属于 V1.6 当前主线。
- V1.8 也不默认落地 API 生图；是否纳入后续自动内容工作流，仍需单独评估。

## 3. 灵感箱新定位

灵感箱从“灵感管理后台”调整为“AI 灵感收件箱”。

用户真实使用路径应当是：

`本地灵感文件夹放图 -> 系统扫描 -> AI 生成商品草稿 -> 用户主要查看草稿 -> 保留 / 放弃 / 转商品`

灵感箱主视图以后应优先展示：

1. 图片。
2. AI 草稿状态。
3. 候选商品名、候选价格、商品类型、目标人群。
4. 用户痛点、使用场景、核心卖点、建议平台、标签、类目建议。
5. 可见文字摘要、规格线索、风险提示。
6. 内容表现力、短视频适配、对比展示能力。
7. 下一步建议、识别质量、草稿初筛分、初筛结论。

任务日志、ScanLog、文件信息、相似度详情应下沉为高级记录或调试信息，不应继续干扰日常主流程。

## 4. 灵感草稿初筛分方案

需要新增并明确“草稿初筛分”，它不等同于商品详情页的正式评分。

草稿初筛分回答的是：

`这张图 / 这条商品线索值不值得继续投入时间`

建议继续采用 100 分制，当前冻结的候选维度为：

1. 内容表现潜力：20 分。
2. 卖点清晰度：20 分。
3. 目标人群清晰度：15 分。
4. 使用场景清晰度：15 分。
5. 风险初筛：15 分。
6. 信息完整度：15 分。

建议结论冻结为：

1. 80-100：优先保留，建议转商品继续评估。
2. 60-79：可以保留，建议补竞品或成本再判断。
3. 40-59：暂存观察，信息不足或卖点不清。
4. 0-39：建议放弃，除非用户有额外理由。

该分数仅用于线索筛选，不代表盈利结论，也不替代正式商品评分。

## 5. 商品创建与转商品

当前“少量字段也能创建商品”的能力必须保留。

冻结要求如下：

1. 不新增新增商品页必填项。
2. 不把新增商品页改成完整评估表。
3. 灵感转商品应改为“AI 草稿预填商品表单 -> 用户确认 -> 创建正式商品”。
4. 所有 AI 预填字段必须可编辑。
5. 必须明确标注“来自 AI 草稿预填，请人工确认”。
6. AI 草稿不能自动创建 `Product`。

## 6. 链接导入降级方案

链接导入后续降级为“辅助来源记录”，不再是核心入口。

冻结建议如下：

1. 从主导航隐藏“链接导入”。
2. 在灵感详情或商品详情中仅保留“来源链接，可选”。
3. 保留现有 `/link-imports` 路由，避免旧数据打不开。
4. 保留 `LinkImportDraft` 数据与 Prisma model。
5. 不做破坏性 migration。

交互表达应明确提示：

`仅凭链接无法稳定识别商品标题、价格或卖点。请上传截图或粘贴页面文本。`

## 7. 商品详情正式评分定位

商品详情页的四块内容仍然有价值，但应从“孤立 Tab”重表达为“正式评估流程”：

1. 竞品参考：别人卖得怎么样。
2. AI 机会分析：AI 从竞品中总结机会和风险。
3. 成本利润：这个商品赚钱吗。
4. 测试结论：综合下来值不值得小批量测试。

正式商品评分回答的是：

`这个正式商品值不值得小批量测试`

它应继续基于规则评分，而不是改成 AI 直接打分。AI 只作为参考输入，不直接覆盖正式结论。

## 8. 竞品截图收件箱方案

该能力建议单列为 V1.7，而不是在 V1.6 中作为小修实现。

核心原则为：

`归属自动，内容待确认`

含义如下：

1. 竞品归属不让 AI 猜，而由文件夹编号确定。
2. 建议目标结构为 `uploads/competitors/{productId}/`。
3. AI 只识别平台、标题、价格、热度、卖点、痛点、规格线索等草稿字段。
4. 用户确认后才进入正式 `Competitor`。
5. 不允许自动污染正式竞品、正式分析和正式评分。

## 9. 商品创建后自动创建竞品目录的影响

已采纳方向：商品创建成功后自动创建：

1. `uploads/products/{productId}/`
2. `uploads/competitors/{productId}/`

这样更符合用户会“同时截商品图和竞品图”的真实习惯。

影响分析如下：

1. 商品创建流程会新增本地目录初始化动作。
2. 空竞品目录是系统保留目录，不应被当作普通垃圾自动清理。
3. 商品详情后续可以围绕目录状态提供入口、扫描和提示。
4. 这会进一步要求 `productId` 保持稳定，不适合在日常删除中自动补位。

## 10. 商品删除、真实 ID 与竞品 ID 冻结建议

当前系统删除商品是软删除，默认不会自动删除素材、竞品、图片或目录。本报告建议维持这一产品方向，不把它改成自动级联文件删除。

冻结建议如下：

1. 删除商品默认仍是业务删除/软删除。
2. 不自动删除商品主图、素材、竞品截图、竞品目录。
3. 文件清理继续走独立的人工确认与回收站流程。
4. `Product.id` 与 `Material.id` 不应因正常删除而自动补位。
5. `Competitor` 需要保留真实 ID，作为正式竞品、截图草稿、分析引用和后续编辑的稳定锚点。

说明：

- 当前开发期真实 ID 整理入口仅是特殊维护工具，不应成为常规业务删除后的自动行为。
- 一旦竞品目录按 `{productId}` 归属，真实 `productId` 更需要稳定，而不是自动重排。

## 11. 商品确认后的自动内容联动方案

这部分应后置，不与 V1.7 竞品截图收件箱混做。

建议两段式规划：

第一段，低成本默认联动：

1. 自动生成多平台文案草稿。
2. 自动生成图片 Prompt 任务。
3. 自动关联到商品。
4. 形成内容生产状态。

第二段，高成本条件联动：

1. 达到草稿初筛分或正式评分阈值。
2. 风险不过高。
3. 信息完整度足够。
4. 用户启用自动生图预算。

满足条件后才考虑更高成本的内容能力。API 生图是否纳入，仍需单独评估，不默认进入 V1.8 主线。

## 12. 当前代码与文档的主要冲突点

已识别的主要冲突如下：

1. 灵感箱当前仍带有较强“管理后台/任务日志”视角，与“AI 灵感收件箱”定位不完全一致。
2. 截图识别与链接导入当前仍作为并列工具页存在，主流程重心不够明确。
3. 链接导入当前仍可能被理解为“平台自动解析入口”，与新方向冲突。
4. 当前灵感扫描是全量重扫源文件夹，并对每张图重新计算 `fileHash`；随着源图累积，扫描成本会线性上升。
5. 当前删除商品是软删除，不会自动清理目录与文件；这与“自动补位 ID”方向天然冲突。
6. 当前竞品截图仍存于 `uploads/products/{productId}/competitors/...`；若未来采用独立 `uploads/competitors/{productId}/`，需单独设计迁移或兼容策略，但不在本次执行。
7. 当前可选 API 生图能力仍可能被用户误解为 V1.6 主线，因此文案和规划必须持续降权。

## 13. 建议版本拆分

### V1.6

定位：真实使用验证、方向同步、主流程重表达。

建议包含：

1. 文档与范围冻结更新。
2. 灵感箱定位切换为 AI 灵感收件箱。
3. 草稿初筛分的产品定义与页面表达设计。
4. 链接导入降级为辅助来源。
5. 商品详情从孤立 Tab 调整为评估流程表达。
6. 记录灵感源文件治理与扫描性能风险，但不以激进自动删除方案解决。

### V1.7

定位：按商品文件夹的竞品截图收件箱。

建议包含：

1. 商品创建后自动创建 `competitors/{productId}` 目录。
2. 商品详情展示竞品目录入口与扫描状态。
3. 扫描指定商品竞品目录。
4. 识别竞品截图并生成 `CompetitorDraft`。
5. 用户确认后转正式 `Competitor`。
6. 正式竞品进入 AI 机会分析与正式评分流程。

### V1.8

定位：商品确认后的自动内容工作流。

建议包含：

1. 商品确认后的低成本内容联动。
2. 评分阈值、风险阈值、预算阈值。
3. 可选高成本内容能力的独立评估入口。
4. 素材库回写与通知。

## 14. 当前不应实现的内容

本轮明确不应直接实现：

1. 竞品截图收件箱代码落地。
2. 自动内容工作流代码落地。
3. 平台爬虫、浏览器自动化、登录态保存。
4. 自动创建正式商品。
5. 自动写入正式竞品。
6. 自动污染正式评分。
7. 自动永久删除文件。
8. 因删除商品而自动补位真实 `Product.id` 或 `Material.id`。
9. 把 API 生图重新抬升为 V1.6 主线或默认自动化步骤。

## 15. Schema / Migration 评估

本次方向同步与文档更新不需要：

1. schema 变更。
2. migration。
3. 依赖变更。

后续判断如下：

1. V1.6 方向同步阶段不应触碰数据结构。
2. V1.7 竞品截图收件箱是否需要新草稿模型，应单独设计后决定。
3. V1.8 自动内容工作流很可能涉及任务状态或编排字段，但必须后置评估。

## 16. 对文件清理与回收站的影响

方向层面的影响已经明确：

1. 当前灵感扫描源文件增长会带来全量重扫成本，后续需要“已处理源文件治理”方案。
2. 未来空 `competitors/{productId}` 目录必须视为系统保留目录，不应自动当垃圾清理。
3. 删除商品不应绕过现有 cleanup/trash 安全体系。
4. 永久删除仍应只针对已进入应用托管 `trash/` 的文件。

## 17. 对 Vercel 只读的影响

没有放宽，反而更强化：

1. 灵感扫描、竞品扫描、目录初始化、上传写入、SQLite 写入和高成本 AI 继续只允许在 Windows 本地运行。
2. Vercel 仍然只提供只读预览，不承担真实验收。

## 18. 主要风险

1. 把“草稿初筛分”和“正式商品评分”混成一套，导致产品语义失真。
2. 继续把灵感箱做成日志后台，而不是草稿收件箱。
3. 链接导入降级不彻底，用户继续误以为系统会自动解析平台页面。
4. 竞品截图收件箱与自动内容工作流混线，形成过大线程。
5. 未来若仍追求删除后自动补位真实 ID，会与文件夹归属、截图挂载、竞品引用和清理安全强冲突。
6. 为解决扫描痛点而贸然引入自动删除，容易带来误删和责任边界不清。
7. 现有可选 API 生图能力若文案降权不彻底，仍可能误导后续版本边界。

2. 在此基础上再决定 V1.6 只做哪些“文档 + 轻量表达调整”。
3. 单独起草 V1.7 竞品截图收件箱设计稿。
4. 单独起草 V1.8 自动内容工作流设计稿。
5. 对灵感源文件治理另开小范围设计，不直接等同于自动删除。
